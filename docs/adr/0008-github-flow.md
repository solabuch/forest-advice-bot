# 0008. GitHub Flow, squash, Conventional Commits

Статус: прийнято · 17.10.2026 · Вимоги: C-05, C-07

## Контекст

- Один розробник, тиждень на завдання.
- Процес має бути видно з репо.

## Рішення

- **Гілки:** `main` і короткі гілки `feat/`, `fix/`, `build/`, `ci/`, `docs/`, `test/`, `refactor/`, `chore/`.
- **Зміни в `main`:** лише через PR із зеленим CI.
- **Merge:** лише squash.
- **Назва PR:** Conventional Commit (перевіряє CI). Вона ж стає повідомленням коміту в `main`.
- **Версії й CHANGELOG:** release-please, semver-теги.

## Наслідки

- Лінійна історія: один коміт на PR.
- CHANGELOG і версії генеруються автоматично.
- Захисту гілок на приватному репо з GitHub Free немає. До відкриття тримаємося дисципліни, при відкритті вмикаємо ruleset на `main`.

## Альтернативи

- **Gitflow** — гілки `develop` і `release` зайві для одного розробника й тижня роботи.
- **Пуш напряму в `main`** — процесу не видно, CI не захищає `main`.
