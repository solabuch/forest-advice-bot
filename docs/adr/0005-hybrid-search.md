# 0005. Гібридний пошук з фільтром області в SQL

Статус: прийнято · 17.10.2026 · Вимоги: R-10, R-11, R-15, R-17, R-24, R-27, D-03, D-08

## Контекст

- У питаннях — імена й числа («Кабан», «4 жолуді») та українська морфологія.
- Пошук має бути суворо в доречних місцях:
  - для рукавички — вона сама, її частини й ліс;
  - для частини — частина й ліс;
  - для лісу — лише ліс.
- Замінені версії документів шукатися не повинні.

## Рішення

1. **SQL-фільтр:** доречні місця за DAG + лише активні версії.
2. **Два пошуки паралельно:** dense (pgvector) і за словами (FTS `simple` + триграми).
3. **Злиття** — Reciprocal Rank Fusion.
4. **Поріг:** нижче нього — чесне «не знайшов поради» (D-08).
5. **Пріоритет:** рукавичка > частина > ліс. Конкретна порада йде першою, загальна — окремо, зі своїм джерелом (R-11, R-24). Поради одного рівня, що різняться, показуються обидві з позначкою (D-03).
6. **Джерела** збирає код з метаданих фрагментів, які модель позначила як використані. Id звіряються зі знайденими.

## Наслідки

- Фрагмент з чужого місця чи замінений варіант не потрапить у відповідь, бо так влаштовано запит, а не промпт.
- Вигадане джерело неможливе.
- Пороги підбираються за eval.

## Альтернативи

- **Лише dense** — слабкий на іменах і числах.
- **Попросити LLM дотримуватися області** — не гарантовано.
