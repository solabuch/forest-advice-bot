# 0010. E2E-тести всередині процесу

Статус: прийнято · 17.10.2026 · Вимоги: C-07

## Контекст

Діалогові сценарії треба перевіряти в CI: документ → ім'я → місце → заміна; питання → перепитування → відповідь. Секретів справжнього Telegram-акаунта в CI бути не повинно.

## Рішення

- **Як подаємо апдейти:** фейкові `Update` → `Dispatcher.feed_update`.
- **Bot API:** виклики перехоплює mock-сесія. Вона записує запити й повертає заготовлені відповіді.
- **БД і LLM:** БД справжня (Postgres у CI), LLM — стаб.
- **Live smoke вручну, перед релізом:** Telethon-клієнт розмовляє зі справжнім ботом.

## Наслідки

- Тести детерміновані й швидкі, у CI немає секретів.
- Специфічні для Telegram речі (ліміти, розмітка, файли) ловить ручний live smoke.

## Альтернативи

- **Лише live-тести** — нестабільні, потребують секретів акаунта, не для кожного PR.
