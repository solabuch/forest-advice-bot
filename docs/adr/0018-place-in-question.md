# 0018. Місце в питанні: словник назв → LLM → кнопки

Статус: прийнято · 18.10.2026 · Вимоги: D-55, R-09, R-18, D-06, D-24

## Контекст

- Звір сам називає місце в тексті питання (R-09).
- Назви бувають різні: відмінки, «у/в», побутові варіанти («Дубова», «прибережна»), описки (Q-55).
- Вгадувати не можна (D-06). Хто питає, бот не враховує (R-18).

## Рішення

1. **Словник назв із `places.yaml`:** офіційні назви в усіх відмінках, «у/в», побутові варіанти, нечіткий збіг для описок із порогом.
2. **Не знайшов → LLM**, що обирає лише зі списку місць.
3. **Невпевнено → кнопки місць** (D-06).
4. **Розпізнане місце бот завжди називає у відповіді** (D-24), тож звір бачить, як його зрозуміли.
5. **Нова назва** — правка `places.yaml` без зміни коду.

## Як влаштовано (`qa/places.py`)

- **Слово → основа + будь-яке закінчення:** «під дубом» ловить «під дубами», «ялиною» — «під ялинкою»; «у / в / ві» взаємозамінні.
- **Прикметник-синонім рукавички** («Дубова») — лише як назва: жіночий рід однини, а далі «рукавичка», кінець речення чи сполучник. Інакше «соснові шишки» стали б рукавичкою «У соснах».
- **Просто «у лісі» — не місце:** так кажуть, питаючи про будь-яку частину. Увесь ліс — «весь ліс», «у всьому лісі», «для всього лісу».
- **Описки:** «прийменник з назви + схоже слово» (≥ 0,8): «під дубм», «в лішині».
- **Кілька згадок:** місце, що вже в області іншого, відкидається («під вербою біля річки» — рукавичка). Лишилось кілька — відповідь для кожного (D-35).
- **Назви місць вирізаються з питання** перед пошуком за словами: «під дубом» не має шукати дуби.

## Наслідки

- Більшість питань обходяться без LLM: детерміновано, швидко, без витрат лімітів Groq.
- Словник покривається тестами й eval-кейсами (відмінки, варіанти, описки, незнайома назва).

## Альтернативи

- **Лише LLM** — недетерміновано й витрачає ліміти на кожне питання.
- **Лише точний збіг** — не розуміє відмінків і описок.
