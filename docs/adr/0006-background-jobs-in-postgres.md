# 0006. Фонові задачі — черга в Postgres

Статус: прийнято · 17.10.2026 · Вимоги: N-03, R-20, D-40, D-53

## Контекст

- Обробка документа (розбір, OCR, embeddings) триває від секунд до хвилин.
- Задачі мають переживати рестарт.
- Архів синхронізується кожні ~15 хв (D-40).
- Кілька документів одним повідомленням обробляються по черзі (D-53).

## Рішення

- Таблиця `jobs` і asyncio-worker, що бере задачі через `SELECT … FOR UPDATE SKIP LOCKED`.
- Важкі для CPU кроки виконуються в executor.
- Повтори з паузою, що зростає.
- Статус бачить автор документа: «готово, можна шукати» або «не вдалося» (R-20).

## Наслідки

- Окремого сервісу немає.
- Незавершені задачі підхоплюються після рестарту.
- Задача й документ змінюються в одній транзакції.

## Альтернативи

- **Redis + arq або Celery** — ще один сервіс, який треба запускати, моніторити й бекапити.
