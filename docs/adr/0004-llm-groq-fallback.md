# 0004. LLM — Groq з fallback між моделями

Статус: прийнято · 17.10.2026 · Вимоги: C-02, N-03, R-20, D-23

## Контекст

LLM — лише безкоштовний Groq (C-02). Ліміти рахуються окремо для кожної моделі:
- запити на хвилину;
- токени на хвилину;
- токени на добу.

Відповіді українською мають бути точними: числа, імена й умови дослівно.

## Рішення

- **Клієнт** — OpenAI-сумісний API Groq.
- **Моделі:** основна + fallback-ланцюжок. На 429 клієнт чекає `retry-after` або переходить до наступної моделі.
- **Формат:** structured output (JSON → pydantic) для класифікації місця й позначення використаних фрагментів.
- **Контекст:** лише знайдені фрагменти, малий бюджет токенів на запит, кеш однакових питань.
- **Вибір моделей** — за міні-бенчмарком українською: точність фактів, формат, чесна відмова.

## Наслідки

- Ліміт однієї моделі не зупиняє бота.
- Якщо вичерпано всі моделі, бот прямо попереджає звіра про затримку (R-20).
- Джерела у відповіді формує код, а не модель (0005).

## Альтернативи

- **Одна модель** — перший же 429 зупиняє відповіді.
- **Локальна LLM** — суперечить C-02 і робить образ дуже важким.
