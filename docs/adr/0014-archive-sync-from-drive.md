# 0014. «Лісовий архів»: синхронізація з Drive + знімок у репо

Статус: прийнято · 17.10.2026 · Вимоги: R-19, R-22, D-40

## Контекст

- Стандартні документи лежать у публічній теці Google Диску, і бот має знати їх від першого старту (R-19).
- Теку можуть поповнювати (D-40).
- Ключ Google API від рев'юера вимагати не хочемо.

## Рішення

- **Синхронізація без API-ключа:** HTML-лістинг публічної теки + пряме завантаження файлів.
- **Знімок у репо:** `data/archive/` + маніфест із розміченими місцями. Це fallback, якщо Диск недоступний, і корпус для eval.
- **Коли:** на старті й кожні ~15 хв.
- **Що змінилося:**
  - нові id → додати;
  - змінена позначка в лістингу → порівняти sha256 → новий варіант;
  - файли, що зникли з теки, перестають використовуватися, але лише після повного успішного лістингу.
- **Байти знімка не нормалізуються** (`.gitattributes`: `-text`) — sha256 збігається з Диском.

## Наслідки

- Бот працює й без доступу до Диска.
- Ендпоінт лістингу неофіційний; якщо він зміниться, лишається знімок.
- Квоту завантажень Диска ділять усі, хто запускає бота, тож завантажуємо лише змінені файли.

## Альтернативи

- **Drive API** — потрібен ключ від рев'юера.
- **Лише знімок** — бот не побачить поповнень теки (D-40).
